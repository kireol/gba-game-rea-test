# Asset provenance

Every visual and audio element in Orbit Drop is generated by this repository's own
code at runtime, from hand-written data (a colour table, a glyph bit table, note
numbers, envelope parameters). There are **no binary asset files** in the project
and **nothing downloaded at build or run time**.

## 1. Policy

The reference's assets may not be extracted, decoded, traced, sampled, converted
or embedded — not even as placeholders, and colour may not be picked from a
screenshot of the reference (project brief § 2.2). This file is the record that we
complied, and how each asset was actually made.

The reference's own screenshots live in `docs/reverse-engineering/screenshots/`,
which is gitignored. They are behaviour documentation only: never shipped, never
imported by the application, never used as an art source. `npm run report` guards
the naming half of the same rule.

Where a look was chosen to *match a measurement* (a 240×160 window, 8-pixel cells,
a 10×20 visible field), that is a geometry finding, not an asset: no pixel, glyph,
palette entry or waveform came from the reference.

## 3. Fonts

No third-party font is bundled, linked or fetched, so there are no OFL-style
licence obligations to record. If a typeface is ever added, add its licence file
under `licenses/` and a row here before merging.

Coverage of the hand-authored table is deliberately stated instead of asserted:
**63 keys** — every one exactly 7 rows of 5 characters, using only `#` and `.` —
covering uppercase A–Z, digits, space and the punctuation the game's own strings
use. Lowercase borrows the capital glyph through `keyFor()`. The printable-ASCII
characters with **no glyph at all** are

```
"  $  [  ]  `  ~
```

and the only key whose glyph carries no ink is the space, which is the point of it.
There is no non-ASCII coverage — `× ° → ♥` are *not* in the table.
Nothing in the shipped UI needs one of those; `canRender()` and `wrapText()` are
the guards, and adding a glyph is a matter of adding one row of `#` and `.`.
(There is no automated coverage test for the table yet — see `TODO.md`.)

## 4. Music and sound, honestly

* There is exactly **one** music loop, and it plays **only while a run's status is
  `playing`** (`setStatus()` starts it, anything else stops it). Menu, pause,
  rules, results and high-score screens are silent. The brief's § 7 "a variation
  per mode family" is therefore **not met** — tracked in `TODO.md` and in the
  milestone report's discrepancies list.
* `SfxName` has no `pause` entry; `mute` is the only UI-state sound beyond menu
  navigation. Pausing is signalled visually.
* All synthesis no-ops when there is no `AudioContext`, so the audio layer cannot
  break a headless run, and nothing is created before the first real gesture
  (`unlock()`), which is what the browser's autoplay policy requires.

## 5. Verification

There is no `assets.test.ts`; the checks that exist are these:

* `npm run report` — the name sweep; also the guard that keeps the reference's
  wordmarks out of everything we author, including this file.
* `find dist -type f ! -name '*.html' ! -name '*.js' ! -name '*.css' ! -name '*.map'`
  — after a production build this prints nothing, which is the machine-checkable
  form of "no binary assets ship".
* `git ls-files | grep -Ei '\.(png|jpg|jpeg|gif|webp|svg|mp3|wav|ogg|m4a|ttf|otf|woff2?|gba|gb|gbc|zip)$'`
  — prints nothing: no image, audio, font or ROM file is tracked.
* The e2e test "player-facing text never carries the reference branding" pins the
  rendered strings; the unit suite pins the rules those strings describe.

## 6. Explicitly absent

No ROM, no emulator core, no decoded tile or map data, no palette copied as a set,
no sampled audio, no transcription of the reference's music, no font files, no
stock art packs, no model-generated imagery with unclear provenance, no favicon or
web-manifest icon (the page has none — see `index.html`'s `<head>`).
